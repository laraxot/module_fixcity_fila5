### 1. Tre fatti che decidono tutto il passo (verificati)
1. **Lo scope CSS non e' ancora acceso per questa pagina.** Dal build delle 13:07 (`public/assets/app-Cy30CRKc.css`) tutto il CSS Design Comuni vale solo sotto `body:has(.page-content[data-dc])` e le regole legacy sono escluse dallo stesso scope (`postcss/isolate-legacy-important.cjs`). `/it/tickets/create` non ha `data-dc` perche' `tickets.create.json` non dichiara `"layout": "design-comuni"` (stesso file in 3 copie: `laravel/config/eu/fixcity/...`, `laravel/config/local/fixcity/...`, `laravel/Modules/Fixcity/config/database/content/pages/tickets.create.json`; `bash bashscripts/tools/cms/page-json-for-url.sh <url>` le elenca). Il Volt `pages/[container0]/[slug0]/index.blade.php` gia' stampa `data-dc` e sceglie `layouts.<layout>` (`isDesignComuni`).
2. **Se il markup e' quello del riferimento, il CSS esistente basta.** Prova: nel browser ho iniettato il `<main>` di `segnalazione-02-dati` dentro `.page-content` e acceso `data-dc` solo lato client: tutte le misure coincidono col riferimento a 1440/768/375 (breadcrumb, stepper 1296x59, navscroll 306x203, `.steppers-content` 856x1477, sezioni 255/654/349, autocomplete 808x113, select 800x64, text-area-wrapper 800x88, cmp-text-area 800x163, btn-wrapper 800x217, info-card 800x199, nav 856x99, pulsanti 82x26/153x48/121x50; a 768: 696x1421, sezioni 263/606/333; a 375: 351x1413, 245/609/349).
