# Piano editoriale FixCity (studio a fondo 2026-10-15)

**Nessuna implementazione runtime.** Scopo: [purpose.md](./purpose.md).

Osservati indici e articoli campione pubblici. Non inventare tassi di
conversione né copiare tono commerciale / stack WordPress.

## 0. Verdict in una frase

AFC insegna l’articolo **operativo** (comportamento + presa in carico);
aferrari insegna l’articolo **sistemico** (journey + KPI + Existing Assets
First). FixCity deve pubblicare **entrambi i registri** in un unico piano a
90 giorni, con CTA verso guida / evento / adozione — mai ads.

---

## 1. Archivio AFC `/blog/` — a fondo

### 1.1 Indice (promessa e titoli)

Fonte: [afcformazione.it/blog](https://www.afcformazione.it/blog/)

Titoli in evidenza osservati:

| Titolo | Pattern del titolo |
|---|---|
| Differenza tra capo e leader: 8 comportamenti concreti | confronto + N comportamenti |
| Errori email marketing: … il cliente sa che cosa fare? | errore + domanda operativa |
| Gestione reclami: … senza mettersi subito in difesa | processo + anti-pattern |
| Lettera aumento prezzi: il modello che chiarisce… | modello + chiarezza |
| Feedback clienti: tre domande che servono più di… | N domande > formula vuota |

**Regola titolo AFC:** problema concreto + angolo comportamentale + spesso
numero o modello. Mai «Il futuro della comunicazione».

### 1.2 Articolo campione — reclami (massima affinità FixCity)

Fonte: [gestione reclami](https://www.afcformazione.it/blog/gestione-reclami-comunicazione/)

Struttura osservata:

1. Scena (cliente segnala; risposta difensiva)
2. Domanda vera («chi prende in carico **adesso**?»)
3. Principio: fatto prima della spiegazione
4. Riconoscere impatto **senza inventarlo**
5. Prima/dopo (esempio didattico dichiarato tale)
6. **4 passaggi** + responsabilità (fatto → impatto → presa in carico → aggiornamento)
7. Limiti / assertività / AI come aiuto non automazione
8. Tabella operativa (passaggio × cosa comunicare × limite)
9. FAQ
10. CTA soft (confronto / mentoring) — non hard sell nel corpo

Criterio ripetuto: «una persona, una scadenza, una verifica».

### 1.3 Articolo campione — capo vs leader

Fonte: [differenza capo/leader](https://www.afcformazione.it/blog/differenza-tra-capo-e-leader/)

Griglia 8 situazioni; criteri urgenza/competenza/rischio; esempi «da adattare»
dichiarati; checklist delega.

### 1.4 Lezione AFC → FixCity

| Pattern AFC | Traduzione Ticket / FO |
|---|---|
| Fatto prima della difesa | Prima ricostruire la segnalazione, poi spiegare |
| Impatto riferito, non inventato | Non promettere tempi inventati al cittadino |
| Una persona / scadenza / verifica | Owner ticket + SLA + aggiornamento |
| Esempio didattico dichiarato | «Esempio da adattare», non fake case Comune |
| Tabella operativa | Checklist cittadino/operatore in Cms |

## 2. Archivio aferrari `/articoli/` — a fondo

### 2.1 Indice (cluster 2026)

Fonte: [aferrari.it/articoli](https://www.aferrari.it/articoli/)

Cluster osservati (set–ott 2026):

| Cluster | Esempi titolo |
|---|---|
| Retention / churn / CLV / referral | Churn rate…; Referral B2B…; CLV…; Retention PMI… |
| Customer marketing post-firma | Dopo la firma, quale contenuto serve… |
| Segmentazione | Tre scelte per smettere di seguirli tutti uguali |
| AI / processi / governance | AI readiness; ROI AI; mappatura processi; governance |
| KPI / journey / allineamento | KPI marketing PMI; Customer journey B2B; Marketing e vendite |

**Regola titolo aferrari:** tesi contro-intuitiva o «prima di X, capisci Y».

### 2.2 Articolo campione — KPI PMI

Fonte: [KPI marketing PMI](https://www.aferrari.it/blog/kpi-marketing-pmi/)

Motore:

1. Tesi: dashboard piena ≠ decisioni
2. Definizione: metrica ≠ KPI (5 domande)
3. **Existing Assets First** — misura con ciò che hai
4. **6 livelli** diagnostici (domanda→…→valore) in tabella
5. Matrice sintomo → KPI mancante → rottura → decisione
6. Anticipatori vs consuntivi
7. Dashboard minima (7 domande)
8. **Test 90 giorni** su una sola frattura
9. Errori tipici + FAQ lunga
10. CTA playbook / confronto

### 2.3 Articolo campione — customer journey B2B

Fonte: [journey B2B](https://www.aferrari.it/blog/customer-journey-b2b/)

Motore:

1. Journey ≠ funnel
2. Osserva il reale (non disegnare l’ideale)
3. Existing Assets First (20 opportunità, email, CRM…)
4. **6 fasi**: innesco→ricerca→shortlist→confronto→allineamento→decisione
5. Tabella fase × domanda × touchpoint × responsabilità × rischio
6. Fratture marketing↔sales
7. Test 90 giorni
8. CTA playbook

### 2.4 Lezione aferrari → FixCity

| Pattern aferrari | Traduzione civica |
|---|---|
| Existing Assets First | Parti da ticket anonimi, FAQ, tempi, Design Comuni — non nuovo CMS |
| 6 livelli KPI | Domanda cittadina → attenzione → invio → qualifica → pipeline uffici → valore pubblico |
| Journey ≠ funnel | Percorso cittadino/Comune ≠ soli stati ticket interni |
| Una frattura / 90 giorni | Un pilastro editoriale alla volta |
| Vanity metric rifiutate | No «pageview blog» come successo |

## 3. Motore unico trasferibile

```text
problema riconoscibile
  → definizione onesta (cosa è / non è)
    → metodo (passi o livelli)
      → strumento (tabella / checklist)
        → esempio «da adattare» o asset esistenti
          → FAQ
            → CTA proporzionata (guida | evento | collabora)
```

Due registri, un motore:

| Registro | Fonte | Persona FixCity | Output tipico |
|---|---|---|---|
| Operativo | AFC | Cittadino / operatore | 4 passaggi, griglia comportamenti |
| Sistemico | aferrari | Dirigente / product / grant | journey, KPI, test 90gg |

## 5. Template articolo (contratto editoriale)

Obbligatori:

1. Titolo = problema + angolo concreto  
2. Persona + problema in una frase  
3. Definizione (è / non è)  
4. Metodo (3–8 passi **o** livelli diagnostici)  
5. Strumento (checklist/tabella) riusabile offline  
6. Esempio anonimizzato o «da adattare»  
7. FAQ (3–8)  
8. **Una** CTA primaria (leggi guida \| partecipa evento \| collabora)  
9. Meta: owner, revisore, fonti, `published_at`, data revisione, locale  

**Vietato:** CTA economica nel corpo; pixel; paywall; fake case; vanity KPI.

Mapping campi Blog: [afc-pattern-adaptation](../../../../Blog/docs/afc-pattern-adaptation.md).

## 7. Metriche sane (da KPI aferrari, civiche)

1. Domanda pertinente (query/FAQ che matchano pillar)  
2. Completamento / ritorno alla guida  
3. Passo CTA (evento o collabora) aggregato  
4. Qualità contatto (Comune vs curiosità)  
5. Avanzamento adozione B2G interna  
6. Impatto servizio (KPI ticket aggregati — Fixcity)  

Niente lead scoring sul cittadino. Niente pageview come unico successo.

---

## 8. Non copiare

- Volume «400 articoli» come obiettivo  
- Tono vendita corsi / mentoring a pagamento  
- UTM/pixel aggressivi senza base giuridica  
- Gate PDF obbligatorio  
- Disegnare journey ideale senza casi ticket reali
