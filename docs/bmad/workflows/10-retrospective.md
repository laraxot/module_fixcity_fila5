# Retrospective

**Perché:** solo le decisioni riusabili entrano nel Second Brain; il resto
ingrossa il contesto senza valore.

## Passi

1. Confrontare AC story vs prove reali.
2. Chiudere o riaprire story; separare blocker ambientali da bug app.
3. Distillare regole stabili nel contratto/wiki modulo — non copiare report lunghi.
4. Rimuovere o stubbizzare docs duplicate (stesso argomento).
5. Appendere voce breve a `docs/wiki/log.md` del modulo (e root se trasversale).

## Gate

Story senza checklist ambigua; riferimenti validi; nessuna memoria duplicata.

## Output

Story chiusa + log aggiornato + backlog residuo prioritizzato.
