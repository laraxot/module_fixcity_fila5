# Frizioni di adozione per operatori comunali

## Richiesta / scopo
Come responsabile di ufficio comunale voglio contenuti e checklist che
parlino delle frizioni quotidiane (non delle feature), così il team adotta
FixCity senza doppia registrazione e senza campi inutili.

## Perché
Studio Asso (*perché il team non usa il CRM*): l'adozione fallisce per
frizione, non per mancanza di slide. Il pillar «comune operativo» deve
diagnosticare frizioni e proporre sblocchi concreti.

## Acceptance Criteria
- [ ] Elenco frizioni tipiche documentato (campi inutili, Excel parallelo,
      assenza vista carico, dirigente fuori flusso).
- [ ] Outline evergreen + checklist «prime 2 settimane di adozione».
- [ ] CTA primaria: demo/laboratorio o guida — non «acquista».
- [ ] Collegamento esplicito a sostenibilità B2G (co-funding / progetto).

## Tasks / Subtasks
- [ ] Intervistare o sintetizzare 3 frizioni da esperienza tenant pilota.
- [ ] Scrivere outline articolo e playbook breve (IM-BLOG-006).
- [ ] Definire KPI adozione: uso settimanale operatori attivi, ticket
      gestiti solo in piattaforma — non login count vanity.

## Owned File / Module Scope
Docs Fixcity + outline in Blog. Nessuna modifica Filament in questa story.

## Testing / Verifica
Review con referente PA pilota; checklist usabile in <15 minuti.
