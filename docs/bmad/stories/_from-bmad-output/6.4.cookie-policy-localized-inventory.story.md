# 6.4 Localized Cookie Policy and inventory

## Story

As a **site visitor**, I want a readable Cookie Policy in my language, so that
I understand each cookie's purpose, duration, type and withdrawal mechanism.

## Acceptance Criteria

1. `/{locale}/cookie-policy` resolves for every supported locale (it, en, de)
   and keeps the active locale in all links.
2. The page inventories every cookie actually emitted by the candidate build,
   including name, purpose, duration, type and optional/necessary status.
3. The page links to the localized privacy notice and explains how to change or
   withdraw the cookie choice.
4. No placeholder, tenant-specific assumption or untranslated legal copy is
   presented as approved production content.

## Tasks / Subtasks

- [ ] Provide the localized Folio page and accessible table (AC: #1, #2)
- [ ] Add it/en/de translation keys and review fallback behavior (AC: #1, #4)
- [ ] Link privacy and withdrawal instructions (AC: #3)
- [ ] Reconcile the inventory with browser capture on staging (AC: #2, #4)

## Dev Notes

- Localization is a MUST platform requirement and tenant content is localized.
  [Source: prd.md#FR-014]
- Compliance copy requires owner approval; code must not infer legal basis.
  [Source: prd.md#NFR-007]
- The current technical baseline uses the session cookie, `XSRF-TOKEN` and
  `__cookie_consent`; this is evidence to verify, not a permanent assumption.
  [Source: Modules/Gdpr/docs/cookiebar-integration.md#Contratto di consenso]

## Testing

- **Approach:** localized feature tests plus browser smoke for each locale.
- **Key scenarios:** 200 page response, translated heading/body/table, privacy
  link, active-locale retention and inventory parity.
- **Per-AC verification:** AC #1 → route matrix; AC #2 → browser cookie diff;
  AC #3 → link/withdrawal assertions; AC #4 → owner approval fixture/checklist.
- **Fixtures / mocks:** it/en/de locale requests and a known cookie inventory.
- **Edge cases:** unsupported locale, absent tenant policy and newly emitted cookie.
