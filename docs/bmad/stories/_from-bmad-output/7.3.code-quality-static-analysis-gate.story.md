# 7.3 Raise and evidence the code-quality gate

## Story

As a **maintainer**, I want static analysis, formatting, tests and ownership rules enforced together, so that quality regressions cannot reach release hidden behind a green happy path.

## Acceptance Criteria

1. The candidate gate defines reproducible commands and versions for PHP syntax, PHPStan at the configured maximum, Pint, relevant Pest/feature tests and browser/view checks.
2. The gate verifies project invariants: strict types, Actions for business logic, no new HTTP Controllers/Services, module ownership, forward-only migrations and immutable `phpstan.neon`.
3. Every failure records command, candidate/commit, environment, scope, timestamp, limitation and owner; environment failures are not converted into passes.
4. Release evidence distinguishes verified, blocked, accepted limitation and not-run states, and 7.1 cannot close while a required quality check is blocked.
5. Any code fix produced by this story is minimal, covered by a focused test where behavior changes, and does not rewrite unrelated dirty-worktree changes.

## Tasks / Subtasks

- [ ] Define the quality command matrix and evidence schema (AC: #1, #3, #4)
- [ ] Add invariant checks for architecture and module ownership (AC: #2)
- [ ] Add a focused regression test for each behavior changed by a quality fix (AC: #5)
- [ ] Link the gate to readiness and sign-off without duplicating their source of truth (AC: #4)

## Testing

- **Approach:** contract tests for the evidence schema plus static-analysis/format/test pipeline execution by the external dev tool.
- **Key scenarios:** clean candidate, PHPStan failure, missing database, browser prerequisite failure and focused behavior regression.
- **Per-AC:** inspect command/version capture, invariant results, failure evidence, readiness block and test linkage.
- **Fixtures / mocks:** isolated candidate configuration and synthetic failed-check evidence; never fake credentials or green output.
- **Edge cases:** dirty worktree, optional browser dependencies, generated views and module subtrees.
