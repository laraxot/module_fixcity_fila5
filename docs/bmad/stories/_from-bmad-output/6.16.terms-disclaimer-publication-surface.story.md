# 6.16 Publish the terms and disclaimer surface

## Story

As a **visitor or reporting citizen**, I want a dedicated localized terms and
disclaimer page, so that service use, external links, user content, availability,
copyright and liability information are not mixed into the privacy notice.

## Acceptance Criteria

1. A localized CMS/Folio page exists for terms and disclaimer in every supported
   locale and resolves through the canonical legal-link contract.
2. The page loads tenant-owned Markdown only; missing, empty or template content
   produces the existing safe incomplete state and never invents legal wording.
3. The page is linked from the public footer and from any flow that asks the user
   to review service terms, using localized URLs.
4. The document is excluded from production readiness until owner approval,
   version and effective date evidence are present.

## Tasks / Subtasks

- [ ] Add the localized page contract and legal-document block (AC: #1, #2)
- [ ] Add the terms/disclaimer document key and translations (AC: #1, #2)
- [ ] Connect footer and terms-review links without duplicate consent runtimes (AC: #3)
- [ ] Extend the legal publication gate metadata contract (AC: #4)

## Dev Notes

- Terms/disclaimer content must remain distinct from privacy and cookie policy; the
  external research is editorial guidance, not legal authority. [Source: bmad-output/research-report.md#Research findings]
- Reuse `BuildLegalDocumentAction` and the existing safe incomplete rendering;
  do not add a controller or second Markdown renderer. [Source: architecture.md#ADR-002a — HTTP resource style]
- The tenant supplies the actual clauses, identity, contacts, dates and version;
  code must not infer them. [Source: prd.md#NFR-007]
- The current wizard contains a terms modal contract but no dedicated public
  destination. [Source: bmad-output/site-audit.md#A-02]
