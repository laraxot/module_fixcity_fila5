# 8.13 Define the frontend component contract
## Story
As a **frontend maintainer**, I want components to have visual, semantic and behavior contracts, so that themes remain coherent and accessible.
## Acceptance Criteria
1. The contract maps Design System Italia patterns to Sixteen and records justified deviations.
2. Components specify semantic HTML, keyboard/focus behavior, responsive states, loading/error/empty states and localization inputs.
3. Runtime remains TailwindCSS + Alpine.js + Lit + DaisyUI + Flowbite with no Bootstrap dependency or markup.
4. Ownership and regression evidence are defined for shared components and alternate themes.
## Tasks / Subtasks
- [ ] Inventory components and assign owners (AC: #1, #4)
- [ ] Document semantic and state contracts (AC: #2)
- [ ] Verify no-Bootstrap boundary and stack mapping (AC: #3)
## Dev Notes
- Bootstrap Italia is reference-only for cookiebar semantics; Bootstrap runtime is forbidden. [Source: bmad-output/project-context.md#Core Constraints]
- Component ownership and theme documentation are a project requirement. [Source: bmad-output/prd.md#FR-017]
- Map Design System patterns without copying an incompatible runtime. [Source: bmad-output/research-report.md#Designers Italia: findings relevant to FixCity]
## Testing
- **Approach:** contract checks, DOM/accessibility tests and dependency scan.
- **Key scenarios:** keyboard navigation, mobile, long localized label and error state.
- **Per-AC:** inspect semantics/states, scan dependencies and verify ownership evidence.
- **Fixtures / mocks:** it/en/de/es labels and alternate theme.
- **Edge cases:** reduced motion, high zoom and missing optional slot data.
