# 9.4 Validate the critical citizen and PA journeys on candidate
## Story
As a **QA/accessibility owner**, I want critical journeys validated on the candidate, so that real users can report, track and process issues before launch.
## Acceptance Criteria
1. Guest discovery/map, citizen A/B isolation, report wizard, upload/map/error/focus, confirmation/tracking and PA role transitions pass on the candidate.
2. Denial, rate-limit, validation, network, queue and notification failure paths return safe localized feedback.
3. Critical Sixteen flows meet WCAG 2.1 AA checks including keyboard, focus, contrast, zoom, reduced motion and screen-reader semantics.
4. Evidence covers it/en/de/es where enabled, mobile/desktop viewports and known exclusions with owner/severity.
## Tasks / Subtasks
- [ ] Run citizen A/B and PA role matrix (AC: #1, #2)
- [ ] Run browser/accessibility matrix (AC: #3, #4)
- [ ] Triage failures and link fixes to owning stories (AC: #2, #4)

## Testing
- **Approach:** Pest/feature plus browser/axe/manual assistive technology checks.
- **Key scenarios:** report, private tracking, upload, map, denial and PA transition.
- **Per-AC:** retain traceable pass/fail evidence per persona, locale and viewport.
- **Fixtures / mocks:** isolated tenant and citizen A/B synthetic accounts.
- **Edge cases:** keyboard-only, slow network, missing geolocation and expired capability.
