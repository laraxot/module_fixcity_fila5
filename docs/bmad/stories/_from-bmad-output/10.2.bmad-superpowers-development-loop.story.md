# 10.2 Standardize BMAD plus development-loop execution
## Story
As a **developer**, I want one BMAD-to-test-to-review loop, so that plugin assistance increases quality instead of creating undocumented changes.
## Acceptance Criteria
1. A ready-for-dev story is the only implementation entry point and every task maps to an AC.
2. Implementation follows inspect → plan → focused change → focused test → review → evidence → Second Brain update.
3. Generated changes preserve Actions/no new Services or Controllers, module ownership, accessibility and localization constraints.
4. Handoff records changed files, tests, limitations and unresolved decisions.
## Tasks / Subtasks
- [ ] Document the execution loop and handoff fields (AC: #1, #2, #4)
- [ ] Add a review checklist for architecture, security, accessibility and scope (AC: #2, #3)
- [ ] Define plugin failure/fallback to local tools (AC: #4)
