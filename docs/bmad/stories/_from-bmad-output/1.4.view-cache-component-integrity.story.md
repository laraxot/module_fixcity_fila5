# 1.4 Restore full Blade view-cache integrity

## Story

As a **release maintainer**, I want every production-reachable Blade component to
resolve during view compilation, so that the release pipeline cannot fail on a
missing Sixteen/Geo component.

## Acceptance Criteria

1. `php artisan view:cache` completes without an unresolved `geo.mappa-static`
   component error.
2. The report-creation test block renders the same map behavior through the
   canonical Geo-owned component namespace, without a duplicate implementation.
3. A focused regression test or compile assertion fails if the component alias is
   removed or renamed.

## Tasks / Subtasks

- [ ] Trace the `<x-geo.mappa-static>` alias and the existing Geo view before editing (AC: #1, #2)
- [ ] Align the alias/include with the canonical Geo component using the existing module convention (AC: #1, #2)
- [ ] Add the smallest focused regression coverage for component resolution (AC: #3)
- [ ] Document the known pre-existing view-cache failure as closed only after the full command passes (AC: #1)

## Dev Notes

- Sixteen owns citizen presentation, while Geo owns geographic functionality; preserve that module boundary. [Source: architecture.md#Module boundaries]
- Actions/models/views remain in their owning module and no new controller or service layer is needed for this fix. [Source: architecture.md#ADR-001 — Domain ownership]
- View compilation is part of the quality gate together with PHPStan, Pest and browser/view checks. [Source: architecture.md#ADR-006 — Quality gate]
- The concrete failure was observed in `Themes/Sixteen/resources/views/components/blocks/tests/segnalazione-crea.blade.php` and the available implementation at `Themes/Sixteen/resources/views/components/blocks/geo/mappa-static.blade.php`. [Inference]

## Testing

- **Approach:** focused Blade/component test plus full view-cache smoke.
- **Key scenarios:** canonical component resolution, report test block compilation, normal non-map views remain unaffected.
- **Per-AC verification:** AC #1 → run view cache; AC #2 → render the block and inspect the map output; AC #3 → remove/alter the alias in a test fixture and assert failure.
- **Fixtures / mocks:** existing Sixteen test page data and Geo map defaults.
- **Edge cases to cover:** missing optional coordinates and a fresh compiled-view directory.

## Dependency Maps

- **Blocked by:** none.
- **Blocks:** 7.1 — release evidence must include a green view-cache check.
- **External:** Laravel Blade compiler; no new dependency.

## Owned File/Module Scope

- `laravel/Themes/Sixteen/resources/views/components/blocks/tests/segnalazione-crea.blade.php`
- `laravel/Themes/Sixteen/resources/views/components/blocks/geo/mappa-static.blade.php`
- `laravel/Modules/Geo/tests/**`

## Learnings from Previous Stories

- Preserve the existing Sixteen-to-module component contract and avoid adding a second map implementation. (from architecture.md#Module boundaries)

### Chiusura AC#3 (2026-10-14, seconda verifica)
- La story era `done` senza test di regressione e con i task non spuntati. `Themes/Sixteen/tests/Unit/BladeTemplatesCompileTest.php` copriva solo `pages` e `components/layouts`: esteso a `components/blocks` (446 template) e aggiunti due casi (alias inesistente che fa lanciare il compilatore, blocco `geo.mappa-static` che compila).
