# 1.1 Canonical component catalog
As a maintainer, I want every module and theme documented, so that work has one owner.
## Acceptance criteria
1. All 19 modules and 4 themes appear in `component-catalog.md` with responsibility and owner.
2. Cross-cutting/high-conflict boundaries and documentation gaps are explicit.
3. Each future story links to an owner component and evidence path.
## Scope
`bmad-output/component-catalog.md`, all module/theme `docs/bmad/` indexes when implemented.
## Verification
Compare catalog to filesystem directories; fail if any first-level module/theme is absent.
