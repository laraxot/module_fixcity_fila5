# 6.14 Record versioned acceptance of legal documents

## Story

As a **service owner and auditor**, I want terms/privacy acceptance to identify the
exact document version, so that a later change does not make historical acceptance ambiguous.

## Acceptance Criteria

1. Registration and report submission distinguish service-terms acceptance from
   GDPR/privacy acknowledgement and cookie preference.
2. A successful acceptance records the document identifier, locale, version or
   content hash and timestamp in the existing approved evidence boundary.
3. A changed or unpublished document cannot be silently accepted as the previous
   version, and an incomplete document blocks the protected flow as today.
4. Existing anonymous cookie choices remain client-side preferences and are not
   converted into fake authenticated legal acceptance records.

## Tasks / Subtasks

- [ ] Inventory current registration/report consent fields and legal links (AC: #1)
- [ ] Define the minimal version/hash evidence contract with Gdpr/User/Fixcity owners (AC: #2, #3)
- [ ] Persist and validate the evidence through existing Actions/events, without duplicating cookie consent (AC: #2, #4)
- [ ] Add regression tests for changed versions, missing content and anonymous visitors (AC: #1, #3, #4)

## Testing

- **Approach:** unit/action tests, database feature tests and browser acceptance checks.
- **Key scenarios:** registration acceptance, report acceptance, locale-specific version, changed hash, unpublished terms, cookie-only visitor.
- **Per-AC verification:** AC #1 → field mapping; AC #2 → persisted evidence assertion; AC #3 → rejection/regression tests; AC #4 → anonymous cookie response inspection.
- **Fixtures / mocks:** approved document versions and fake authenticated user/tenant.
- **Edge cases:** simultaneous publication change, locale fallback, replayed submission and consent withdrawal.
