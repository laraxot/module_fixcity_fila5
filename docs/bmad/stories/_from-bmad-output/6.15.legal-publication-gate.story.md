# 6.15 Gate publication of tenant legal content

## Story

As a **release owner**, I want legal documents to fail the publication gate while
they are templates, incomplete or unapproved, so that a candidate cannot be called
ready with placeholder legal content.

## Acceptance Criteria

1. The publication gate checks privacy, terms/disclaimer, legal notes, media policy
   and accessibility declaration for every enabled tenant/locale.
2. A missing file, placeholder, missing approval/version or incomplete required
   section produces a named actionable failure and blocks the gate.
3. A complete owner-approved fixture passes and records document versions, locales,
   tenant, command, timestamp and limitation in release evidence.
4. The normal test suite does not hide the gate; the explicit candidate command can
   run it without mutating production content.

## Tasks / Subtasks

- [ ] Extend the existing privacy/accessibility publication-gate pattern to the legal document inventory (AC: #1, #2)
- [ ] Add terms/disclaimer, legal-notes and media-policy completeness checks (AC: #1, #2)
- [ ] Add approved multilingual fixtures and evidence output (AC: #3)
- [ ] Document the explicit candidate command and its owner/QA handoff (AC: #4)

## Dev Notes

- Release completion requires evidence on the candidate environment, not merely source files or local green tests. [Source: bmad-output/release-plan.md#Go/no-go]
- The project already uses explicit `PUBLICATION_GATE=1` tests for privacy and accessibility; preserve that safe default and fail closed when invoked. [Source: laravel/Modules/Fixcity/tests/Feature/Pages/PrivacyPolicyPublicationGateTest.php]
- Legal content cannot be approved by a code agent; the gate should verify evidence supplied by the owner. [Source: prd.md#NFR-007]
- The current EU/local configuration contains privacy/terms placeholders and an empty accessibility declaration, so this gate must remain red until owner data exists. [Source: bmad-output/research-report.md#What exists in FixCity]

## Testing

- **Approach:** explicit publication-gate feature suite plus release-evidence integration test.
- **Key scenarios:** every locale, every legal document missing/placeholder/incomplete, approved complete tenant, wrong hash/version, and disabled optional document.
- **Per-AC verification:** AC #1 → tenant/locale matrix; AC #2 → failure report assertions; AC #3 → passing fixture/evidence assertions; AC #4 → command isolation and no mutation check.
- **Fixtures / mocks:** approved and incomplete tenant directories, legal metadata and deterministic clock.
- **Edge cases:** fallback locale, duplicate document versions, unsafe Markdown and inaccessible external URLs.
