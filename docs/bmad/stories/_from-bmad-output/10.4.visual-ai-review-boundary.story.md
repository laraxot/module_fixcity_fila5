# 10.4 Standardize visual review evidence
## Story
As a **UX/QA owner**, I want visual and DOM review repeatable, so that design plugins improve the Sixteen interface without replacing accessibility or candidate testing.
## Acceptance Criteria
1. Each visual review records route, locale, viewport, candidate commit, reference, screenshot and known limitation.
2. Cookiebar, disclaimer/legal surfaces and critical citizen flows include DOM, keyboard and accessibility evidence in addition to screenshots.
3. Figma or another visual plugin is optional and cannot be treated as installed, connected or authoritative without confirmation.
4. Differences become BMAD stories or documented accepted limitations with owner and retest date.
## Tasks / Subtasks
- [ ] Define visual evidence schema and storage convention (AC: #1, #4)
- [ ] Add DOM/keyboard/WCAG fields for legal and cookie surfaces (AC: #2)
- [ ] Document optional visual-plugin boundary (AC: #3)

## Testing
- **Approach:** evidence schema validation and representative screenshot/DOM fixture review.
- **Key scenarios:** mobile/desktop, four locales, reduced motion and incomplete legal content.
- **Per-AC:** verify metadata, accessibility evidence, plugin state and retest linkage.
- **Fixtures / mocks:** synthetic pages and screenshots.
- **Edge cases:** font/rendering drift and unavailable visual service.
