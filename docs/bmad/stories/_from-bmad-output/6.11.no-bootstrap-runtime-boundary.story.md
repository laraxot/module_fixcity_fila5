# 6.11 Enforce the Sixteen no-Bootstrap runtime boundary

## Story

As a **Sixteen maintainer**, I want production assets and active public components
to have a verifiable no-Bootstrap runtime boundary, so that the site consistently
uses TailwindCSS, Alpine.js, Lit, DaisyUI and Flowbite as required.

## Acceptance Criteria

1. The production Sixteen build contains no Bootstrap CSS/JS import, `window.bootstrap`
   dependency or Bootstrap runtime initialization.
2. Active public components using dropdowns, tabs, modals, accordions and tooltips
   work through the approved existing stack or a documented native fallback, with
   keyboard and focus behavior preserved.
3. Legacy, showcase and Bootstrap Italia sprite assets are either excluded from the
   production entrypoint or explicitly classified as non-runtime assets in the
   component inventory.
4. A repeatable static/build check prevents reintroducing Bootstrap runtime imports
   or `data-bs-*` behavior in the production boundary.

## Tasks / Subtasks

- [ ] Identify production Vite entries and classify active, legacy and showcase files (AC: #1, #3)
- [ ] Remove or replace only active runtime Bootstrap imports and initialization paths (AC: #1, #2)
- [ ] Verify critical public interactions with the existing Alpine/Lit/Tailwind stack (AC: #2)
- [ ] Add a narrow static/build gate for forbidden runtime imports and attributes (AC: #4)

## Dev Notes

- The locked Sixteen decision keeps Bootstrap Italia semantic familiarity but forbids Bootstrap runtime; the cookiebar is already Tailwind/Alpine/DaisyUI. [Source: bmad-output/decision-log.md#Cookiebar senza Bootstrap runtime]
- Sixteen owns citizen presentation and must use existing Folio/Volt/Filament entry points; do not add a controller or a new UI framework. [Source: architecture.md#ADR-002 — UI boundary]
- The current audit found a Bootstrap import in `resources/js/components/bootstrap-italia.js`, a Vite CSS reference, `window.bootstrap` usage and 217 view files with `data-bs-*`. [Source: bmad-output/site-audit.md#A-03]
- Preserve the Bootstrap Italia visual/sprite contract where it is only an asset/markup dependency; the acceptance boundary concerns executable runtime and production bundle behavior. [Inference]

## Testing

- **Approach:** static source scan, production asset build inspection, and browser keyboard smoke on critical active components.
- **Key scenarios:** mobile navigation, language menu, modal, tabs, accordion, tooltip, map modal and cookiebar.
- **Per-AC verification:** AC #1 → build manifest and forbidden-import scan; AC #2 → browser interaction matrix; AC #3 → entrypoint/classification review; AC #4 → CI check with a known forbidden fixture.
- **Fixtures / mocks:** production Vite entry list and minimal forbidden-import fixture.
- **Edge cases to cover:** code-split chunks, dynamically imported components, legacy pages accidentally included by the build, and reduced-motion/focus behavior.
