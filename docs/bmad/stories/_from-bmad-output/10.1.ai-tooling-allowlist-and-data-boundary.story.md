# 10.1 Govern agent and plugin usage
## Story
As a **project maintainer**, I want an allowlist and data boundary for agent plugins, so that automation improves delivery without exposing tenant or production data.
## Acceptance Criteria
1. Each enabled/requested plugin has purpose, owner, permissions, data classes, retention and connection status.
2. Secrets, personal data, legal drafts, production logs and credentials are explicitly denied by default.
3. Plugin output cannot bypass BMAD acceptance criteria, tests, module ownership, Gdpr or release approval.
4. The register distinguishes installed, connected, suggested and unavailable states.
## Tasks / Subtasks
- [ ] Create the plugin register and data-classification rules (AC: #1, #2, #4)
- [ ] Define review and revocation procedure (AC: #1, #3)
- [ ] Link plugin changes to stories and decision log (AC: #3)

## Testing
- **Approach:** policy/schema validation and negative data-flow review.
- **Key scenarios:** suggested but unconnected, connected read-only, revoked plugin and sensitive file request.
- **Per-AC:** verify state, owner, permissions, denied classes and release linkage.
- **Fixtures / mocks:** synthetic tenant data only.
- **Edge cases:** plugin dependency change and accidental credential in logs.
