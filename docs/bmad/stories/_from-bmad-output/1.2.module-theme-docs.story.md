# Story 1.2 — Organizzare docs di moduli e temi

## Obiettivo

Come agente o sviluppatore voglio trovare rapidamente la fonte canonica della
documentazione senza perdere lo storico né confondere report, decisioni e raw
evidence.

## Acceptance criteria

- [ ] ogni perimetro conserva `README.md` e `00-INDEX.md` come ingressi;
- [ ] ownership Cms/Sixteen e cross-project è esplicita;
- [ ] la tassonomia distingue architecture, wiki, BMAD, stories e evidence;
- [ ] nessun file viene cancellato o rinominato senza migration map e link check;
- [ ] QMD, Graphify e Second Brain hanno ruoli documentati;
- [ ] l'indice CMS rimanda al tema e viceversa;
- [ ] la baseline brownfield cita questa architettura.

## Scope file

- `bmad-output/docs-architecture/`;
- `bmad-output/project-documentation.md`;
- indici dei moduli/temi solo quando il relativo audit lo richiede.

## Verifica

Controllare con `find` l'esistenza degli ingressi, `rg` i link, `git diff --check`
e una ricerca QMD dopo il re-index. La story non autorizza modifiche applicative.
