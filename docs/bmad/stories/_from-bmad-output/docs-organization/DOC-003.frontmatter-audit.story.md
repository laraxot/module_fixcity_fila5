# DOC-003 — Audit front matter

## Obiettivo

Rendere ricercabili e classificabili i documenti nuovi senza riscrivere in massa
lo storico.

## Acceptance criteria

- [ ] ogni nuovo documento ha `title`, `type`, `status`, `updated`, `tags`, `qmd`;
- [ ] i file raw/generated sono marcati evidence o archive;
- [ ] i file senza front matter sono solo elencati in un report;
- [ ] le correzioni automatiche hanno dry-run e diff revisionabile;
- [ ] nessun contenuto viene eliminato dal parser.

## Verifica

Usare il controllo front matter esistente o uno script dry-run, salvare il report
per perimetro e passare `git diff --check`. Escludere `raw/`, screenshot e lock.
