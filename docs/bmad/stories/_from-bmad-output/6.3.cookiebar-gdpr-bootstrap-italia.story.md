# 6.3 Bootstrap Italia Cookiebar backed by Gdpr

## Story

As a **site visitor**, I want a clear cookie choice, so that optional
processing does not start before my consent and I can reach the preferences.

## Acceptance Criteria

1. HTML responses render exactly one `.cookiebar` through the Gdpr-owned
   Statikbe middleware; the theme does not manually inject a second banner.
2. The UI uses TailwindCSS + Alpine.js + DaisyUI and contains no Bootstrap CSS,
   Bootstrap JS, or `data-bs-*` attributes.
3. `Solo necessari` and `Accetto` persist the configured Statikbe values in
   `__cookie_consent` by default and hide the banner on the next visit.
4. The banner exposes keyboard-accessible controls and a localized preferences
   link; consent is explicit and not inferred from navigation.
5. Gdpr remains the owner of consent categories, revocation and authenticated
   audit; anonymous cookie choice is not written as a fake server-side audit.

## Tasks / Subtasks

- [ ] Keep Statikbe middleware as the only global injection path (AC: #1, #5)
- [ ] Maintain the vendor view override and canonical Sixteen component (AC: #1, #2)
- [ ] Bind Alpine actions to `config/cookie-consent.php` values (AC: #3, #4)
- [ ] Remove or reject duplicate manual layout integrations (AC: #1, #2)

## Dev Notes

- Statikbe is already a Gdpr module dependency and its middleware injects the
  consent view before `</body>`. [Source: architecture.md#Module boundaries]
- The semantic `.cookiebar` contract is retained, but Bootstrap runtime is
  forbidden by the Sixteen stack. [Source: decision-log.md#Cookiebar senza Bootstrap runtime]
- Consent evidence belongs to Gdpr and tenant-owned legal content must be
  approved before production. [Source: prd.md#NFR-007]
- Do not add Spatie beside Statikbe: two runtimes would create competing
  cookies and consent semantics. [Source: Modules/Gdpr/docs/cookiebar-integration.md#Scelta tra i package]

## Testing

- **Approach:** Blade rendering, feature response inspection and browser E2E.
- **Key scenarios:** first visit, each action, reload, duplicate detection,
  keyboard navigation and localized link generation.
- **Per-AC verification:** AC #1 → one middleware-rendered banner; AC #2 →
  forbidden-attribute/runtime scan; AC #3 → cookie persistence; AC #4 →
  keyboard/browser test; AC #5 → Gdpr boundary review.
- **Fixtures / mocks:** configured Statikbe cookie values and it/en/de locales.
- **Edge cases:** existing consent, disabled banner flag, non-HTML responses,
  ignored paths and missing optional translation.

## Learnings from Previous Stories

- Keep the middleware as the single injection point; manual layout includes caused duplicate banners. (from prior 6.3 implementation)
- Localized URLs must use `LaravelLocalization::localizeURL()`, not `url()` with a fixed path. (from Sixteen localization work)
