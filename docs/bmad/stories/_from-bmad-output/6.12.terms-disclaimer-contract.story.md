# 6.12 Define the localized terms and disclaimer contract

## Story

As a **tenant owner and site visitor**, I want a dedicated localized terms/disclaimer
document, so that the reporting service rules are distinct from privacy and cookie
information.

## Acceptance Criteria

1. A canonical CMS/Folio document contract exists for `it`, `en` and `de`, with a
   documented optional `es` policy, title, slug, owner, publication date and last update.
2. The document separates service terms, acceptable use, content/media rules,
   external services/links, availability and legally reviewed liability wording.
3. The page never publishes generic placeholders; it shows the existing safe
   incomplete-state pattern until tenant content is approved.
4. Footer, registration and report flows link to the localized document without
   using `#` or confusing terms acceptance with cookie/GDPR consent.

## Tasks / Subtasks

- [ ] Define the document key, localized slug and metadata contract in the existing CMS pattern (AC: #1)
- [ ] Add the legal-content checklist without writing legal clauses on behalf of the tenant (AC: #2, #3)
- [ ] Connect the page and all relevant links through the existing localization helper (AC: #4)
- [ ] Add feature tests for incomplete and owner-approved content in it/en/de (AC: #1, #3, #4)

## Dev Notes

- CMS/Folio pages and tenant localized content are the established public-page boundary. [Source: architecture.md#ADR-002a — HTTP resource style]
- Tenant privacy and legal semantics require owner approval; agents must not infer legal basis or publish invented copy. [Source: prd.md#NFR-007]
- Existing legal documents use `GetPublishedLegalDocumentAction` and sanitized Markdown with an incomplete warning; extend this pattern. [Source: laravel/Modules/Fixcity/app/Actions/BuildLegalDocumentAction.php]
- The research found terms files still contain “Edit this file” and no dedicated disclaimer contract was evident. [Source: bmad-output/research-report.md#What exists in FixCity]

## Testing

- **Approach:** feature tests for localized CMS pages and link inventory, plus browser smoke for the public footer and report/registration entry points.
- **Key scenarios:** missing content, placeholder content, complete owner content, locale switch, and direct access without cookie consent.
- **Per-AC verification:** AC #1 → content matrix; AC #2 → owner checklist fixture; AC #3 → no placeholder publication assertion; AC #4 → link/locale assertions.
- **Fixtures / mocks:** tenant terms Markdown for it/en/de with a publication metadata fixture.
- **Edge cases:** unsupported locale, stale translation, missing owner metadata and accidental `#` link.
