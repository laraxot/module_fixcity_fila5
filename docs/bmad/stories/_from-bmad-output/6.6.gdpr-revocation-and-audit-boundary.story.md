# 6.6 Gdpr revocation and audit boundary

## Story

As a **registered citizen or privacy administrator**, I want consent changes and
revocations represented in the Gdpr model, so that accountable decisions remain
auditable without pretending anonymous choices identify a person.

## Acceptance Criteria

1. Authenticated consent flows continue to use Gdpr treatments, `ConsentType`
   and existing audit events; the theme creates no parallel persistence model.
2. An anonymous cookie choice is stored only in the configured browser cookie and
   is never assigned to a user without an authenticated, explicit action.
3. Revocation removes or disables optional processing on the next safe boundary
   and leaves an auditable authenticated event where an identity exists.
4. Tenant isolation and authorization prevent one tenant/user from reading or
   mutating another subject's consent evidence.

## Testing

- **Approach:** unit and feature tests for actions/models/policies plus audit assertions.
- **Key scenarios:** authenticated grant, authenticated revoke, anonymous choice,
  tenant mismatch, unauthorized read/write and retention boundary.
- **Per-AC verification:** AC #1 → existing treatment/event assertions; AC #2 →
  database absence; AC #3 → revoke behavior; AC #4 → policy tests.
- **Fixtures / mocks:** users, tenants, treatments, consent records and request identities.
- **Edge cases:** deleted user, expired treatment version, repeated revoke and replay.
